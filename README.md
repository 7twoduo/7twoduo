## Security and Infrastructure Philosophy

I believe strong cloud engineering is not just about deploying resources. It is about building systems that are secure, explainable, repeatable, and operationally useful.

The patterns I focus on are:

| Principle | Meaning |
|---|---|
| **Least Privilege** | Access should be scoped to only what is required. |
| **Private by Default** | Sensitive workloads should not be directly exposed to the public internet. |
| **Infrastructure as Code** | Environments should be repeatable, versioned, and reviewable. |
| **Auditability** | Important actions should leave evidence that can be reviewed later. |
| **Operational Visibility** | Logs, metrics, alarms, and traces should support real troubleshooting. |
| **Security by Design** | Security controls should be part of the architecture, not added at the end. |

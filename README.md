## About Me

I am a cloud security and infrastructure engineer focused on designing, building, and securing AWS environments.

I have **6+ years of hands-on project-based experience** working with cloud infrastructure, security-focused architecture, automation, and infrastructure deployment. My work is centered on practical engineering: building real systems, troubleshooting real infrastructure problems, and creating cloud environments that reflect enterprise patterns.

My strongest areas are **AWS infrastructure**, **Terraform**, **cloud networking**, **IAM/security controls**, **secure multi-tier architecture**, and **production-style cloud project development**.

I am especially interested in cloud security engineering, zero-trust access systems, compliance-aware infrastructure, DevSecOps, and AI-assisted incident response.

### AI-Powered Incident Response Platform

I am currently building an AI-powered incident response platform for AWS environments.

The goal is to help teams detect infrastructure and security issues, visualize affected cloud resources, investigate incidents faster, and generate useful findings from AWS telemetry.

The long-term direction is to support:

```text
CloudWatch Alarms
      ↓
Event Collection Layer
      ↓
CloudTrail + CloudWatch Context
      ↓
AI-Assisted Investigation
      ↓
Incident Timeline + Evidence
      ↓
Guided Remediation Recommendations
```

Core capabilities I am designing toward:

- CloudWatch alarm ingestion
- CloudTrail event analysis
- AWS resource health visualization
- AI-assisted investigation workflows
- Incident timeline generation
- Evidence collection
- Scoped AWS role access for investigation
- Guided remediation recommendations

## Security and Infrastructure Philosophy

I believe strong cloud engineering is not just about deploying resources. It is about building systems that are secure, explainable, repeatable, and operationally useful.

| Principle | Meaning |
|---|---|
| **Least Privilege** | Access should be scoped to only what is required. |
| **Private by Default** | Sensitive workloads should not be directly exposed to the public internet. |
| **Infrastructure as Code** | Environments should be repeatable, versioned, and reviewable. |
| **Auditability** | Important actions should leave evidence that can be reviewed later. |
| **Operational Visibility** | Logs, metrics, alarms, and traces should support real troubleshooting. |
| **Security by Design** | Security controls should be part of the architecture, not added at the end. |
